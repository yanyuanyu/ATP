# 新发现问题修复与复验（2026-09-28）

本报告补充并更新 PERFORMANCE_FIX_VALIDATION.md 中的恢复边界。
环境：Windows / Docker Desktop，Core Ultra 7 155H，Python 3.12、gmssl 3.2.2。
隔离验收部署：http://127.0.0.1:18080/；不覆盖旧 hack-* 演示容器，不删除身份卷。

## 修复内容

1. **慢域阻塞**：移除整批 20 条 gather 屏障，改为持续调度；
   最多 4 个活动目标域，每域一个在途请求，0.1 秒接纳新任务，单次传输上限 8 秒。
   按轮次让未服务目标域优先，防止四个慢域持续占满槽位；
   停止时取消并等待所有子任务，重启恢复未完成状态。
2. **确认丢失后错误退信**：首次发送前持久化最终密文；
   每次尝试携带新 SM2 签名凭据，绑定同一业务消息的 SM3 摘要。
   接收端原子提交收件和持久化回执，新尝试匹配回执时返回 already_accepted，
   不重复入箱；同 nonce 不同内容返回冲突，不把普通 replay 错误当作成功。
3. **旧消息无法恢复**：业务 nonce、时间戳、密文和签名保持不变，
   传输尝试拥有独立的新鲜度和防重放校验。普通消息的 300 秒窗口不放宽。
   传输仍必须通过 ATS、原消息 ATK、尝试凭据 ATK 和尝试重放检查。
4. **ATS 过宽**：三个 zone 从整个 /16 改为三个接收网关域内地址。
   单元测试明确拒绝 NAT 地址、Docker 网关地址和普通 Agent 地址。
5. **测试污染**：每轮合法投递、重启和离线恢复使用独立测试邮箱，
   不再反复读取旧验收产生的大量 64 KB 邮件；未删旧消息，也未强改重试计时器。
6. 保留邮箱大小写不敏感查找，同时不修改已签名/加密的消息字段。
7. **64 KB 密码运算抖动**：本轮优化前均值 1.863 秒、最大 2.239 秒。
   SM3 摘要/HMAC 改用环境可用的 OpenSSL 原生 SM3，不可用时回退相同算法的 gmssl。
   标准向量、空输入/64 KB 跨实现摘要一致性及双向密文兼容均有回归。
8. **部分 SM2 公钥偶发加密失败**：随机密钥回归发现 gmssl 将公钥裸坐标
   开头的 04 误删。会话密钥封装路径恢复已验证的完整坐标，
   与原有签名路径一致；增加固定 11*G 公钥边界测试，不靠随机重跑掩盖失败。

## 必须保留的边界

双方 ATP 都要升级；旧后端不认识新凭据，不能获得旧消息/丢确认恢复保证。
新增 outbound_wire、transfer_receipts 表自动迁移，必须备份并保留整个 messages.db；
回执不自动过期，长期运行需要监测存储增长。升级前已在途但未缓存密文的旧消息，
不能凭空重建接收证据；存在歧义时应核对接收记录，不能手动换 nonce 重发付款。

ATS 在该代理拓扑验证可信接收网关 IP，发送域身份由 ATK 绑定；
不声称能通过 NAT/代理识别原始主机。隔离测试使用对应的 172.30.* 网关地址。
100% 仅对应预设有限样例，不是任意攻击保证。

恢复有有限重试次数和资源上限，不保证无限停机、无限积压或所有硬件均在 30 秒内恢复。
收件大批量解密耗时随消息数量增加；常驻 Agent 使用 after_id 游标，本轮验收邮箱不混入旧负载。
幂等回执保证服务端不重复入箱，不代替业务付款系统自己的事务与幂等设计。
64 KB 的 2 秒指标指密码运算，不是包含网络、签名和排队的端到端时延。
密码运算基准包含 SM4-CBC、HMAC-SM3、SM2 会话密钥封装/解封；两次预热不计样本。
原生 SM3 不可用时功能仍可用，但必须在目标环境重新测时，不能沿用此性能结果。
临时 Compose 包含模型凭据，不得分发；报告和测试输出不包含私钥/API 密钥。
