# 模型状态与流程校验改进

日期：2026-09-27。开发分支：`fix/model-state-workflow`。

## 实现

- 本地进程状态与模型连接状态分离。第一次实际请求成功后记录连接成功时间；业务等待超时不会误标为模型接口失败。
- 密钥、模型不可用、额度不足、限流、网络异常、模型超时、ATP 等待超时和任务总超时采用中文错误分类。
- 捕获 Pi 消息中的 `stopReason/errorMessage`，不再依赖抛出异常判断模型调用成功。
- 控制器执行期限 180 秒；运行时 175 秒取消，模型请求和阶段等待均有独立期限，限制 24 次工具调用。取消后关闭适配器并隔离迟到事件。
- 五条业务回复按任务/上下文 ID、请求 nonce、发送方校验；三条价格按事件序号去重。付款参数须匹配已接收的价格与晚数，成功总结由验证过的付款数据生成。
- 搜索工具兼容 `巴黎` 和 `Paris`。搜索及付款回复直接序列化业务工具结果，避免模型改写关键字段。
- 完整回归会重启服务 Agent 并清理旧消息，保存模型、耗时、Travel 工具调用次数、证据和结果报告。

- Node 离线测试：12 passed，使用真实 Pi 循环和本地假模型 HTTP 服务，覆盖完整流程、401、404、额度不足、429、模型超时、任务超时、ATP 无回复、缺少证据、重复/过期消息及付款拒绝。
- 前端 TypeScript 检查及生产构建通过；生成的静态资源已更新。
- 真实模型：DMXAPI `qwen3.7-plus`，运行 `run-20260927-123921`，56.1 秒，7 次 Travel 工具调用（发送 3、接收 3、查询状态 1），273 条网络信号。五条业务回复齐全，模拟付款最低每晚 170 USD、两晚 340 USD。完整回归含 TLCP 抓包检查通过。

最终版本重复运行 `run-20260927-124200`：55.84 秒，6 次工具调用（发送 3、接收 3），268 条网络信号；关联结果和 TLCP 检查再次通过。

首次真实回归暴露了城市名称别名缺失：库存为空时价格被正确拒收，任务返回中文“未完成”，没有虚报成功；修复别名后通过。

原始报告在本机 `traces/regressions/`，不随源码提交。网络和模型结果有波动，通过的回归不代表以后每次调用必然成功。已发送的跨域请求无法撤回；任务超时不等于付款一定未执行，不会自动重发付款。业务仍是模拟支付。

## 复现

参见 [README.md](README.md) 中“模型状态与任务校验”。运行 `bash scripts/test-demo-controller.sh`，或先执行不收费的 `node --test guards.test.mjs runtime.test.mjs`。Windows 离线测试需设置 `ATP_PYTHON` 为可用的 Python 路径。

WSL 构建 Go 依赖源无法连接时，可设置 `GOPROXY=https://goproxy.cn,direct` 后运行 `scripts/build-tlcp.sh`。本次同时修复证书脚本中仅 Git Bash 支持的 `pwd -W` 用法，支持 Linux/WSL。
