# 本地集成验证

验证日期：2026-09-25。环境：Windows 11 + Docker Desktop，Python 3.12 容器，gmssl 3.2.2，Go 1.24.7 构建的 TLCP 网关，Pi 0.80.6；使用本地 BIND9 及已配置的模型接口。

## 通过的检查

- 仓库 Python 单元测试：309 passed，2 条依赖弃用警告；`compileall` 与 `pip check` 通过。
- TLCP 网关 Go 单元测试：4 passed；SM2 CA、签名证书、加密证书生成及密钥对加载通过。
- 前端 TypeScript/Vite 生产构建通过：1665 个模块完成转换。
- Docker Compose 配置校验通过，DNS、三域 ATP、三个 TLCP 网关、三个服务 Agent 与演示控制器共 11 个默认服务保持运行。
- family→hotel 实际请求协商 `TLCPv1.1`，密码套件为 `ECC-SM2-SM4-CBC-SM3`，远端能力接口返回 200；非白名单目标返回 403。
- SM4/TLCP 集成测试：hotel 数据库中只出现 `sm4-cbc-sm3` 密文信封和 SM2 封装会话密钥，未出现明文标记；本地接收接口成功验签、解密并返回原始载荷。
- 实际 HTTPS 跨域请求：有效 SM2 签名返回 202；同一请求重放返回 400；修改载荷或将算法改为 Ed25519 均返回 403。
- 三域服务器重启：SM2 公钥均未改变；重启后再次通过验签及拒绝测试；Search、Rates、Bill 进程仍运行。
- 历史四 Agent 真实模型演示：`run-20260923-024822`，13 次 Travel 工具调用，223 条网络信号。通过搜索、三次价格订阅、最低价 170、两晚总价 340 的模拟预订付款检查，以及四角色审计和 DNS/TCP/TLS 证据检查。本次 2026-09-25 回归未重新向外部模型发送该测试提示词。
- 演示后 family 数据库有 5 条带 SM2 签名的接收消息；另有 3 条本地提交的未签名发送记录，域间发送时由 DeliveryManager 签名。
- JavaScript、PowerShell、Bash 变更脚本语法检查通过。前端沿用已验证构建产物。
- 提交前检查未包含本机 API Key、私钥、证书目录、数据库、日志或 node_modules。

## 已修复问题

1. SM2 私钥排除不可签名的 `n-1`，生成范围同步修正。
2. ATP 服务及演示控制器使用 Starlette lifespan，兼容新版移除的启动/关闭回调参数。
3. Docker 直接构建本仓库源码，启动显式选择 SM2，DNS 更新使用同算法公钥，重启不重新生成密钥。
4. 服务 Agent 遇到接收连接短暂中断时重试，保留适配器及接收游标。
5. 构建路径不依赖固定盘符；增加可选 Python 依赖源及 Windows/WSL 说明。
6. 三域增加 TLCP 网关与 SM2 双证书，默认跨域传输使用 SM2/SM3/SM4，保留 TLS 1.3 配置兼容模式。
7. 跨域载荷采用随机 SM4 会话密钥，SM2 封装会话密钥，密文和元数据由 SM3 认证并由 ATK 再签名。

## 限制

这些结果证明本地演示集成通过，不代表安全认证或生产环境审计。SM2/SM3 用于消息签名验签，跨域载荷使用 SM4 加密并由 SM2 封装会话密钥，跨域传输使用 TLCP；浏览器及本地 Agent 接入没有改成 TLCP。业务库存、价格与支付均为模拟。依赖下载及模型调用需要网络；模型结果存在波动。

源代码包启动仍需要构建或导入 Docker 镜像、填写自己的模型密钥、生成本机证书并更新 DNS 公钥。比赛离线镜像包尚需另行准备。
