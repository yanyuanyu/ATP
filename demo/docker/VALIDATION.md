# 本地集成验证

验证日期：2026-09-23。环境：Windows + WSL Ubuntu Docker Engine，Python 3.12 容器，Starlette 1.6.0，gmssl 3.2.2，Pi 0.80.6；使用本地 BIND9 镜像及 DMXAPI 配置。

## 通过的检查

- 仓库单元测试：276 passed，2 条依赖弃用警告。
- 实际 HTTPS 跨域请求：有效 SM2 签名返回 202；同一请求重放返回 400；修改载荷或将算法改为 Ed25519 均返回 403。
- 三域服务器重启：SM2 公钥均未改变；重启后再次通过验签及拒绝测试；Search、Rates、Bill 进程仍运行。
- 四 Agent 真实模型演示：`run-20260923-024822`，13 次 Travel 工具调用，223 条网络信号。通过搜索、三次价格订阅、最低价 170、两晚总价 340 的模拟预订付款检查，以及四角色审计和 DNS/TCP/TLS 证据检查。
- 演示后 family 数据库有 5 条带 SM2 签名的接收消息；另有 3 条本地提交的未签名发送记录，域间发送时由 DeliveryManager 签名。
- JavaScript、PowerShell、Bash 变更脚本语法检查通过。前端沿用已验证构建产物。
- 提交前检查未包含本机 API Key、私钥、证书目录、数据库、日志或 node_modules。

## 已修复问题

1. SM2 私钥排除不可签名的 `n-1`，生成范围同步修正。
2. ATP 服务及演示控制器使用 Starlette lifespan，兼容新版移除的启动/关闭回调参数。
3. Docker 直接构建本仓库源码，启动显式选择 SM2，DNS 更新使用同算法公钥，重启不重新生成密钥。
4. 服务 Agent 遇到接收连接短暂中断时重试，保留适配器及接收游标。
5. 构建路径不依赖固定盘符；增加可选 Python 依赖源及 Windows/WSL 说明。

## 限制

这些结果证明本地演示集成通过，不代表安全认证或生产环境审计。SM2/SM3 当前用于消息签名验签；尚无 SM4 载荷加密或国密 TLS。业务库存、价格与支付均为模拟。依赖下载及模型调用需要网络；模型结果存在波动。

源代码包启动仍需要构建或导入 Docker 镜像、填写自己的模型密钥、生成本机证书并更新 DNS 公钥。比赛离线镜像包尚需另行准备。
