# 三域隔离与恢复修复验收（2026-09-28）

后续发现的慢域阻塞、确认丢失、旧消息恢复及 ATS 范围问题已继续修复；
最新结果和替代本报告恢复边界的说明见 PERFORMANCE_RETRY_FIX_VALIDATION.md。

本报告覆盖本轮代码修复，优先于 PERFORMANCE_ACCEPTANCE_20260928.md 中修复前的结论。
实测环境：Windows/Docker Desktop，Core Ultra 7 155H，Python 3.12.14、gmssl 3.2.2、Pi 0.80.6。

## 修改

- 默认 docker-compose.yml 已采用 family/hotel/payment 三个独立 /24 域网络及 TLCP 骨干网。
  ATP 与业务 Agent 仅加入本域；DNS 和管理控制器为跨网基础设施。网关中继端口仅绑定域接口，
  TLCP 端口仅绑定骨干接口。证书私钥维持 0600，由网关 uid 65534 持有。
- 重试间隔 2–4、4–6、8–10 秒，1 秒扫描，最多 4 路并发，单次传输 8 秒上限；
  默认最多 60 次重试。服务器入口 exec 转交信号，缩短关闭等待。
- 重启重新入队中断的 delivering 消息；旧长重试计时器收敛到 10 秒内。
  nonce、时间戳、身份密钥不变，已投递/退信记录不复活，保留验签及重放防护。
- 抓包支持网关全部接口，增加骨干与旅行控制器地址映射；旧验收脚本改经 TLCP 访问远域，
  移除部分固定 WSL/机器路径，离线演示不再强制改重试计时器。
