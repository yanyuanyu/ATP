# ATP 性能与功能验收实测

测试日期：2026-09-27。代码基线：`171739501799fe93f3f4132e1fbadc15913a7f36`，分支 `fix/model-state-workflow`。本轮新增测试脚本，未修改生产实现以改变测试结果。

**结论：不能无条件宣布五项全部达标。** 国密载荷性能、预设合法及攻击样例、单服务重启和本轮真实模型流程通过；独立网络域部署尚不满足严格隔离解释，整组顺序重启及积压消息恢复未达到 30 秒。

## 环境与口径

- Windows / Ubuntu WSL2，Linux 6.6.87.2，Docker 容器；Intel Core Ultra 5 125H，容器可见 18 个逻辑处理器，内存约 7.42 GiB。
- Python 3.12.14、gmssl 3.2.2。模型：通过 DMXAPI 调用 `qwen3.7-plus`。
- 三个域为 family.test、hotel.test、payment.test；四个业务角色为旅行、搜索、价格、结算。
- 结果适用于此次本机环境，并非比赛指定机器的保证。KB 在载荷测试中按 KiB，即 1024 字节计算。
- 原始结果在 `traces/acceptance/`，该目录被 Git 忽略，随源码分发时需另行包含脱敏测试证据。

### 国密耗时的计算范围

每种大小预热 2 次。对准确为 1024 / 65536 字节的 JSON 明文执行 SM4-CBC 加密、HMAC-SM3、SM2 包装密钥及对应解密、校验、解包；报告平均加密与解密耗时之和。

| 明文 | 加密平均 | 解密平均 | 合计平均 | 合计 P95 |
| --- | --- | --- | --- | --- |
| 1 KiB | 21.05 ms | 16.25 ms | 37.30 ms | 44.70 ms |
| 64 KiB | 591.15 ms | 577.30 ms | 1168.45 ms | 1240.15 ms |

以上不包含 ATP 消息签名、网络、投递队列及轮询耗时。额外完整 64 KiB 队列投递、接收及解密耗时为 **4.178 s**。若比赛的 2 秒实际上要求端到端投递，则本次不达标。直接 TLCP 测试中多次读取已有收件箱也会增加耗时，不应与纯密码运算混为一谈。

证据：`traces/acceptance/benchmark-serial.json`、`queued-64k.json`。另一次密码基准平均为 38.49 ms / 1.089 s；表格采用后续独立运行结果。

### 合法与攻击样例

合法样例：family 分别向 hotel/payment 投递，1 KiB、64 KiB 各 3 次，共 12 次。全部返回 202，接收端实际取得明文并与原文一致。跨域使用 TLCPv1.1 / ECC-SM2-SM4-CBC-SM3。

攻击样例：重放 12、内容篡改 10、签名后修改发送身份 10、本地身份不匹配 5、错误凭据 5、禁止的 TLCP 目标 5、ATS 白名单外来源 5，共 52 次，均拒绝。ATS 独立测试使用有效签名但来自 172.29.250.0/24 的请求，5 次均为 403；临时网络已清理。

**额外边界测试不能忽略：** 当前各域 ATS 均放行整个 `172.28.0.0/16`。另一组有效签名请求经 NAT 后，服务端看到来源 `172.28.0.1`，5 次均被接受。按现行规则该来源属于白名单，但说明它不能区分 NAT 前的来源；不能据此宣称任意未授权来源均会拒绝。需要明确比赛攻击样例与信任边界，收窄授权并配合网络隔离。此次没有证明攻击者无需合法签名就能冒用身份。

证据：`network.json`、`ats.json`、`ats-nat-observation.json`。100% 仅指上述固定样例，不是完整安全性证明。DNS 测试验证域服务发现，尚未单独验收按能力动态搜索未知智能体。

### 重启测试

从发出 Docker 重启命令开始计时，直到实际跨域消息收到并解密成功；不仅检查健康接口。比较各服务 SM2 密钥文件重启前后哈希，仅输出一致性，不输出密钥。

- 单独重启 family、hotel、payment 各一次，均小于 30 秒，身份密钥全部一致。
- 连续三轮 `docker restart` 顺序重启三个服务，全部健康需要约 31.7–32.2 秒，两条真实通信完成需要约 45–46 秒，密钥全部一致。此结果不能解释为单个服务启动用了 46 秒。
- hotel 离线期间提交消息，等自然投递失败进入重试后启动 hotel；从启动命令到收到原消息用时 64.094 秒。未修改数据库重试时间，也未手动重新发送。

证据：`restart-single.json`、`recovery.json`。

### 真实模型与展示证据

运行编号 `run-20260927-134642`：qwen3.7-plus，49.27 秒，旅行 Agent 工具调用共 6 次（3 次发送、3 次接收）。五条关联业务回复完整，三次报价、最终单价 170、合计 340 及模拟付款结果通过验证。四角色审计、DNS ATS/ATK/SVCB、TLCP 握手及应用数据证据通过，共 259 条抓包信号。

本轮通过已有回归脚本检查拓扑/轨迹/通信证据数据及前端资源；未另做浏览器画面验收。事件订阅验收范围为演示工作流内的三次价格事件，不代表已验证通用持久订阅系统。真实模型存在随机性，本轮成功不能替代连续多轮成功率测试。

证据：`traces/run-20260927-134642.report.json`、`traces/regressions/run-20260927-134642.json`、`traces/acceptance/llm.log`。

## 复现

以下从仓库根目录 PowerShell 执行；要求现有 Docker 演示服务及挂载已启动。重启测试会中断演示，真实模型测试会调用已配置的 API 并重置演示工作流状态。ATS 脚本暂时使用 172.29.250.0/24 网络，运行前确认该网段未占用。脚本内挂载路径按本机目录配置，移动项目后需调整。

```powershell
wsl -d Ubuntu -- docker exec hack-server-payment python /agents/acceptance_probe.py benchmark
wsl -d Ubuntu -- docker exec hack-server-family python /agents/acceptance_probe.py network
wsl -d Ubuntu -- docker exec hack-server-family python /agents/acceptance_probe.py transfer hotel 65536
.venv/Scripts/python.exe demo/docker/scripts/acceptance-ats.py
.venv/Scripts/python.exe demo/docker/scripts/acceptance-recovery.py --single
.venv/Scripts/python.exe demo/docker/scripts/acceptance-recovery.py
wsl -d Ubuntu -- bash -lc 'cd /mnt/d/学习/atp_bundle/team-ATP/demo/docker && bash scripts/test-demo-controller.sh'
```

脚本输出需要检查布尔结果及状态码，不能只凭退出码判断通过。重复运行会增加验收收件箱消息，影响端到端读取耗时；密码微基准不读取收件箱。

## 达到更严格验收的后续改动

1. 将三个域部署到不同网络并通过明确的网关连接，收窄 ATS 授权来源；增加 NAT、跨域越权及不同身份边界测试。
2. 调整失败消息的重试调度，让服务恢复后积压消息也能在 30 秒内投递；采用有界退避与抖动，并验证恢复时不会集中重试。
3. 检查容器入口进程的信号传递与退出等待，支持并行恢复，重新测试单服务及整组故障。
4. 在比赛指定机器上复测密码基准与网络性能，并对真实模型完整流程做连续多轮统计。

上述是待实施改动，本次没有将它们计为已完成。
